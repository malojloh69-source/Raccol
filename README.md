# Панель рассылки для Telegram — без папок

Архив содержит **три файла в корне**: `app.py`, `requirements.txt`, `README.md`. Интерфейс встроен в `app.py`; при первом запуске рядом автоматически появится **один файл** `sessions.sqlite3` с сессиями пользователей. Папки с сайтом, скриптами или сессиями не нужны.

Каждый пользователь входит по **своему номеру и коду** Telegram и видит только свои группы, каналы, журнал и отправку. Одна пара `API_ID`/`API_HASH` настраивается для всего приложения. Поддерживается пароль двухэтапной проверки, если он включён у конкретного аккаунта.

Можно вручную выбрать чаты, написать текст и задать интервал **30–3600 секунд**. Приложение проходит по списку **один раз**, отправляя по одному сообщению в каждый выбранный чат (максимум 50). Личные переписки не предлагаются. Отправку можно остановить; при ограничении частоты Telegram она прекращается автоматически.

## Запуск

1. Установите Python 3.11 или новее. Рядом с `app.py` выполните:

   ```bash
   python -m pip install -r requirements.txt
   ```

2. Получите **свои** `API_ID` и `API_HASH` в [my.telegram.org](https://my.telegram.org), раздел **API development tools**. Это обязательные параметры Telegram для входа пользовательского аккаунта. Секретный `API_HASH` не публикуйте.

3. Укажите переменные окружения (пример для Linux/macOS):

   ```bash
   export API_ID=123456
   export API_HASH='ваш_api_hash'
   python app.py
   ```

4. Откройте `http://127.0.0.1:8080`. Панель сразу показывает вход по номеру телефона: дополнительный пароль панели при локальном запуске не нужен.

5. Каждый пользователь открывает эту же панель в своём браузере, вводит **свой** номер в формате `+79991234567`, затем свой код из Telegram. Если на аккаунте включена двухэтапная проверка, приложение дополнительно запросит пароль. После входа пользователь выбирает свои чаты, текст и интервал. Кнопка «Выйти» отзывает его сессию в приложении.

## Данные и размещение

- Код и пароль двухэтапной проверки не записываются. Авторизованные сессии разных пользователей хранятся отдельными записями в одном файле `sessions.sqlite3`. **Этот файл даёт доступ к аккаунтам:** не передавайте его и не включайте в архивы/репозитории. Выход удаляет запись конкретного пользователя и пытается отозвать его сессию в Telegram; при сбое сети её можно завершить вручную в настройках Telegram. Записи старше 30 дней очищаются при запуске сервера.
- Доступ к своему аккаунту сохраняется в браузере с помощью отдельного защищённого cookie. На общем устройстве нажимайте «Выйти» после работы. Пользователь не может использовать выбранный чат другого пользователя: список и адресаты проверяются на сервере отдельно для каждой сессии.
- Панель по умолчанию доступна только на `127.0.0.1`. Для внешнего доступа используйте **HTTPS**: вне локального режима cookie помечается как `Secure` и по обычному HTTP работать не будет. Не вводите коды через незащищённое соединение.
- Программа не запрашивает токен BotFather: сообщения идут **от подключённых пользовательских аккаунтов**. Сервер должен сохранять `sessions.sqlite3` между перезапусками и запускаться в одном процессе, чтобы вход по коду и текущие задания не разрывались между разными процессами.
- Отправляйте сообщения только в чаты, где у вас есть разрешение. Telegram запрещает спам; фиксированная пауза не гарантирует отсутствие ограничений аккаунта.

Для хостинга основной файл — `app.py`. Установите зависимости из `requirements.txt`, задайте `HOST=0.0.0.0`, `PORT` вашего хостинга, `API_ID` и `API_HASH`. Нужен HTTPS-домен и постоянное хранение `sessions.sqlite3`; если хостинг удалит его, пользователи войдут заново. Если переходите с предыдущей версии, старые файлы в `data/` больше не используются: завершите те сессии в настройках Telegram и удалите старые файлы.

Для реальной работы нужны доступ к Telegram и ваши учётные данные. Код и пароль для входа вводите только на своём HTTPS-домене.
